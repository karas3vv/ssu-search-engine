# Гибридный поиск Tantivy + BGE-M3

Гибрид использует уже готовые индексы: локальный Tantivy и коллекцию BGE-M3 в Qdrant. Статьи не переиндексируются. На один поисковый запрос вычисляется один эмбеддинг через MWS.

## Проверка и запуск

Из папки проекта при запущенном Qdrant:

```bash
python -m habr_search.evaluation.evaluate_hybrid \
  --qdrant-url http://127.0.0.1:6333 --check-only
```

Эта команда проверяет наборы статей, наличие ожидаемых документов и длину контрольных запросов. Ключ не нужен, обращений к MWS нет, отчёт не создаётся. При отсутствии токенизатора скачивается только публичный файл токенизатора BGE-M3.

Запуск страницы:

```bash
./run.sh --engine hybrid
```

Откройте http://127.0.0.1:8000. Другой порт: `./run.sh --engine hybrid --port 8001`. Остановка — Ctrl+C. Ключ MWS вводится скрыто в терминале или читается из `MWS_API_KEY`. Открытие страницы, подсказки и «Показать ещё» не вызывают модель; новый поиск вызывает её один раз.

По умолчанию используются `data/tantivy/` и коллекция BGE-M3 с настройками фрагментов 1024/128. При отсутствии `MWS_EMBEDDINGS_MODEL` выбирается деплоймент `bge-m3`; ранее заданная переменная может переопределить его. Коллекция вычисляется из тех же параметров, что при индексации BGE-M3.

Для другого индекса Tantivy добавьте `--tantivy-path`. Для гибрида словарь берётся из этой папки, отдельный словарь BGE-M3 строить не нужно. Он предлагает исправление после появления результатов; текст меняется только после нажатия. `--without-spelling` отключает подсказки.

## Как объединяется выдача

1. Исходный запрос проверяется и отправляется в BGE-M3 обычным текстом.
2. Qdrant возвращает до 20 разных статей по одному вектору запроса.
3. Tantivy возвращает до 20 статей по словам того же запроса.
4. RRF объединяет списки по местам: вклад источника равен `вес / (rrf-k + место)`; по умолчанию веса равны 1:1, а `rrf-k=60`. Если статья есть в обоих списках, её вклады суммируются. BM25 и косинусные оценки напрямую не складываются.
5. Для каждой статьи остаётся одна карточка. Отрывок берётся из Tantivy, если статья присутствовала в его кандидатах; иначе — из подходящего фрагмента Qdrant.

При равных оценках используется воспроизводимый порядок: лучшее место в источниках, затем место BGE-M3, затем id статьи. Страница получает до 20 карточек и показывает их по пять. Оценка `score` в API гибрида — RRF, а не косинусное сходство и не вероятность релевантности. `--min-score` и `--raw-query` в этом режиме не применяются.

Настройки эксперимента: `--candidate-limit` от 1 до 100, положительные `--rrf-k`, `--dense-weight` (BGE-M3) и `--lexical-weight` (Tantivy). Для веб-приложения глубина должна быть не меньше 20. Исходные значения — 20 и 60; отдельные исключения под контрольные запросы не добавлены.

## Сравнение трёх режимов

```bash
python -m habr_search.evaluation.evaluate_hybrid \
  --qdrant-url http://127.0.0.1:6333 --timeout 300
```

По умолчанию проверяются 40 запросов `evaluation/benchmark_dev.csv`, top-5. Это **40 обращений к MWS суммарно**, а не 40 на каждый режим. Скрипт отдельно выводит Hit@5, MRR@5, запросы без ответа и время для BGE-M3, Tantivy и гибрида, в том числе по категориям.

Результат записывается в новый `data/evaluation/hybrid-*.csv`. Сохраняются оба списка кандидатов, объединённая выдача, версия каждого индекса, параметры и время. Формат отличается от обычного отчёта семантического поиска и не предназначен для калибровки косинусного порога.

Время BGE-M3 включает один вызов MWS и поиск её кандидатов в Qdrant. Время Tantivy включает локальную выдачу с отрывками. Время гибрида включает весь запрос: модель, проверки версии, оба поиска и объединение. Загрузка приложения, HTTP браузера и опечаточник в эти измерения не входят. Все три измерения относятся к одному прогону, с одной глубиной кандидатов; исторические замеры top-5 могут отличаться.

### Продолжение после остановки

```bash
python -m habr_search.evaluation.evaluate_hybrid \
  --qdrant-url http://127.0.0.1:6333 --timeout 300 \
  --resume data/evaluation/hybrid-ИМЯ-ПРЕДЫДУЩЕГО-ОТЧЁТА.csv
```

Каждый завершённый запрос сразу записывается и сбрасывается на диск. При продолжении сохранённые запросы не вызывают MWS повторно, создаётся новый CSV. Когда весь набор уже сохранён, ключ вообще не запрашивается. Автоматических повторов при ошибке модели нет. Если модель уже обработала запрос, но результат не успел попасть в CSV, его повторная отправка при продолжении может снова тарифицироваться.

Параметры, контрольный набор и версии обоих индексов должны совпасть. Обычный CSV BGE-M3 с top-5 нельзя передать через `--resume`: в нём отсутствуют полные кандидаты Tantivy и более глубокая выдача BGE-M3.

## Бесплатное сравнение весов

После полного прогона кандидаты уже сохранены. Их можно пересортировать без ключа, MWS, Qdrant и открытия индекса Tantivy:

```bash
python -m habr_search.evaluation.tune_hybrid \
  --report data/evaluation/hybrid-20261024-135206-206955.csv
```

Укажите имя своего полного отчёта. По умолчанию сравниваются 12 сочетаний: веса BGE-M3 1, 1.5, 2, 3 при весе Tantivy 1 и `rrf-k` 2, 10, 60. Другие небольшие сетки задаются через `--dense-weights` и `--rrf-values`. Списки кандидатов и их глубина остаются исходными. Переоценка не может добавить отсутствующую статью.

Команда создаёт `data/evaluation/fusion-grid-*.csv` со всеми вариантами и отдельный `*-queries.csv` с изменениями по каждому запросу для выбранного варианта. Сохраняются отпечаток исходного отчёта, версии индексов и параметры. Исходный файл и настройки сервера не меняются. Частичный или несовместимый отчёт отклоняется.

Основной критерий выбора — число попаданий в top-k, затем MRR. Это не означает, что выбранная настройка одновременно максимизирует все метрики. Новая задержка не измеряется; старое время не выдаётся за время нового эксперимента.

На dev-прогоне 24 октября 2026 года вариант 1.5:1 и `rrf-k=10` дал Hit@5 32/36 (88,89%) и MRR@5 0,7926 вместо 31/36 и 0,7755 у исходного гибрида. Новых попаданий — одно, потерь попаданий нет; места улучшились у пяти запросов, ухудшилось одно. Вариант 1:1 и `rrf-k=2` имел больший MRR 0,8125, но только 31 попадание. Поэтому перед переключением нужно проверить выбранную настройку на отложенном наборе:

```bash
python -m habr_search.evaluation.evaluate_hybrid \
  --qdrant-url http://127.0.0.1:6333 \
  --queries evaluation/benchmark_holdout.csv \
  --dense-weight 1.5 --lexical-weight 1 --rrf-k 10 --timeout 300
```

Это уже вызывает MWS по одному разу на контрольный запрос. Отложенный набор при подборе весов не использовался. Команда одновременно показывает BGE-M3 и Tantivy для тех же запросов, дополнительных вызовов для сравнения не нужно.

Для явного запуска страницы с выбранными параметрами:

```bash
./run.sh --engine hybrid --dense-weight 1.5 --lexical-weight 1 --rrf-k 10
```

Без этих флагов прежние веса и `rrf-k` сохраняются. Новые отчёты версии 2 содержат веса; старый формат версии 1 читается как 1:1. Продолжать старый эксперимент с другими весами нельзя — для него используйте офлайн-сравнение либо отдельный новый прогон.

## Актуальность и ограничения

При запуске сравниваются множества id статей обоих индексов; при расхождении гибрид не начинает платный поиск. Изменение числа точек или версии Qdrant во время работы требует перезапуска. Совпадение id само по себе не доказывает совпадение текстов: после изменения корпуса обновите оба индекса и перезапустите приложение. Tantivy работает со снимком, открытым при запуске.

RRF может поднять статьи, найденные обоими источниками, но способен опустить подходящую статью из одного списка. Если нужной статьи нет среди кандидатов, объединение её не восстановит. Поэтому улучшение качества пока не считается подтверждённым: нужен полный прогон dev-набора, затем проверка на holdout после выбора настроек. Автоматического решения для запросов без ответа в гибриде пока нет.

## Код

- `habr_search/retrieval/hybrid.py` — конфигурация, проверка источников и RRF.
- `habr_search/retrieval/tantivy_index.py` — более глубокая выборка кандидатов и чтение id снимка.
- `habr_search/web/app.py`, `HybridService` — общий путь с одним вызовом модели и отложенной подсказкой.
- `habr_search/evaluation/evaluate_hybrid.py` — сравнение трёх режимов и продолжение CSV.
- `habr_search/evaluation/tune_hybrid.py` — офлайн-сравнение весов по кандидатам.
- `tests/test_tune_hybrid.py` — проверки старых и новых CSV, весов и отсутствия обращений к сервисам.
- `tests/test_hybrid.py` — автономные проверки объединения, индексов, API и возобновления после сбоя.

Описание подхода: [RRF и гибридный поиск в документации Qdrant](https://qdrant.tech/documentation/search/hybrid-queries/#reciprocal-rank-fusion-rrf). Сами списки Tantivy и Qdrant объединяются в Python по id статей.
