# Архитектура поисковика по Хабру

Для приложения используем отдельный Qdrant в Docker. На этапе разработки Python-команды запускаются на компьютере пользователя, а Gemma вызывается по API MWS. Встроенный режим Qdrant оставлен для автономных тестов.

## Два независимых процесса

**Индексация** выполняется при добавлении или обновлении корпуса:

```text
SQLite с полными статьями
  → prepare.py: проверка и очистка
  → chunking.py: фрагменты с метаданными
  → Gemma в MWS: векторы
  → Qdrant в Docker: векторы и тексты фрагментов
```

**Поиск** выполняется для каждого пользовательского запроса:

```text
пользователь → search.py → Gemma в MWS → Qdrant → статьи с подходящими отрывками
```

Индексатор реализован в `habr_search/ingestion/index.py`, поиск из терминала — в `habr_search/retrieval/search.py`. Локальный API и страницу поиска запускает `habr_search/web/app.py`. При поиске статьи повторно не скачиваются и весь корпус заново не векторизуется. Ключи MWS и Qdrant использует Python-приложение; браузер обращается к его API.

## Запуск Qdrant на своём компьютере

Нужны Docker Engine и Docker Compose. Все команды выполняются из корня проекта:

```bash
python -m pip install -r requirements.txt
docker compose up -d qdrant
```

В `compose.yaml` закреплён образ `qdrant/qdrant:v1.19.2`. Порт `6333` привязан к `127.0.0.1`: сервер доступен с этого компьютера. Данные и снимки сохраняются в именованных Docker volumes, поэтому остановка контейнера их не удаляет.

Проверить доступ:

```bash
curl -fsS http://127.0.0.1:6333/collections
```

Панель управления: [Qdrant Dashboard](http://127.0.0.1:6333/dashboard).

Пробный запуск не вызывает MWS и не подключается к Qdrant:

```bash
python -m habr_search.ingestion.index --limit 5 --dry-run --qdrant-url http://127.0.0.1:6333
```

Настоящая индексация пяти статей:

```bash
python -m habr_search.ingestion.index --limit 5 --qdrant-url http://127.0.0.1:6333
```

Команда попросит ключ MWS или возьмёт его из `MWS_API_KEY`. При наличии новых фрагментов она отправит тексты в MWS и запишет векторы в серверный Qdrant. Повторные запуски пропускают уже сохранённые фрагменты.

Чтобы не указывать адрес каждый раз, можно задать переменную окружения:

```bash
export QDRANT_URL=http://127.0.0.1:6333
python -m habr_search.ingestion.index --limit 5
```

Явный `--qdrant-url` важнее переменной окружения. Явный `--qdrant-path` выбирает встроенный режим даже при установленном `QDRANT_URL`. Без URL и без явного пути сохраняется прежний встроенный режим `data/qdrant/`, чтобы существующие команды продолжали работать. `--qdrant-url` и `--qdrant-path` нельзя указывать одновременно.

Остановить сервер без удаления данных:

```bash
docker compose stop qdrant
```

Просмотреть журнал:

```bash
docker compose logs --tail 50 qdrant
```

## Поиск по сохранённым статьям

После пробной индексации пяти статей:

```bash
python -m habr_search.retrieval.search --query "Как автоматизировать работу с Excel?" --top-k 3 --qdrant-url http://127.0.0.1:6333
```

Команда проверяет коллекцию, просит ключ MWS и получает один вектор запроса. Qdrant возвращает разные статьи, для каждой показываются заголовок, ссылка, лучший фрагмент и косинусное сходство. Сходство не является процентом правильности. Корпус SQLite при поиске не читается, коллекция не изменяется.

Поисковая инструкция добавляется к запросу в формате из [документации Gemma](https://huggingface.co/BAAI/bge-multilingual-gemma2). Если ваш сервер сам добавляет эту инструкцию, используйте `--raw-query`, чтобы не дублировать её. Для документов инструкция не добавляется.

Адрес MWS, имя деплоймента, `--max-tokens` и `--overlap-tokens` должны совпадать с индексацией: от них зависит имя коллекции. Запрос вместе с инструкцией ограничен 1024 токенами; слишком длинный запрос отклоняется без обращения к MWS. `--snippet-chars` меняет только длину показанного отрывка.

Пять статей подходят для проверки соединения и выдачи. Если подходящей статьи среди них нет, поиск всё равно покажет ближайшие доступные статьи. После проверки можно увеличить индекс до 100 статей:

```bash
python -m habr_search.ingestion.index --limit 100 --qdrant-url http://127.0.0.1:6333
```

Существующие фрагменты будут пропущены. Сначала стоит оценить время, расход API и качество на этом объёме, затем индексировать остальной корпус.

## Контрольные запросы и оценка поиска

`habr_search/evaluation/evaluate.py` проверяет текущий семантический поиск на наборе `evaluation/queries.csv`. В стартовом наборе 18 запросов к шести статьям, включая перефразировки, варианты названий и опечатки. Набор предварительный и сосредоточен на офисной автоматизации; его разметку и разнообразие предстоит расширить.

```bash
python -m habr_search.evaluation.evaluate --dry-run
python -m habr_search.evaluation.evaluate --limit 3 --qdrant-url http://127.0.0.1:6333
```

Первый запуск проверяет только CSV. Второй получает три вектора запросов через MWS и выводит Hit@5 и MRR@5. Отчёты сохраняются в `data/evaluation/`, статьи не векторизуются повторно, индекс не изменяется. Полный запуск без `--limit` обрабатывает все 18 запросов. Подробности о разметке, метриках и отчётах — в [evaluation/README.md](evaluation/README.md).

## Расширение до 500 статей

Для следующей оценки подготовлены два набора: 32 запроса для настройки и 16 отложенных запросов. Они основаны на полных текстах 12 статей из первых 500 записей подготовленного корпуса; статьи между наборами не пересекаются. Старый набор из 18 проверок сохранён.

```bash
python -m habr_search.ingestion.index --limit 500 --qdrant-url http://127.0.0.1:6333 --timeout 300
```

Пробное разбиение текущего корпуса дало 2571 фрагмент на 500 статей. Расширение требует новых обращений к MWS, уже сохранённые точки пропускаются. После завершения индексации оценивается `evaluation/queries_dev.csv`; отложенный `evaluation/queries_holdout.csv` используется после выбора настроек. Подробности и основания разметки — в [evaluation/EXPANDED.md](evaluation/EXPANDED.md).

## Если Qdrant находится на удалённом сервере

Тот же Compose можно запустить на сервере. Для доступа со своего ПК можно использовать SSH-туннель:

```bash
ssh -N -L 6333:127.0.0.1:6333 user@server
```

Затем на своём ПК используется адрес `http://127.0.0.1:6333`. В команде SSH замените `user@server` реальными данными подключения. Если порт 6333 на ПК занят, выберите другой локальный порт.

Для уже настроенного защищённого Qdrant или Qdrant Cloud задаются HTTPS-адрес через `QDRANT_URL` и ключ через `QDRANT_API_KEY`. Ключ в исходниках и командах Git не хранится. Для открытого удалённого HTTP-адреса клиент не отправляет API-ключ; используйте HTTPS или локальный адрес SSH-туннеля.

Позже Python API и Qdrant можно разместить на одном сервере в Docker-сети. Тогда приложение обращается к `http://qdrant:6333`, где `qdrant` — имя сервиса. Адрес `127.0.0.1` внутри контейнера приложения указывает на само приложение, а не на контейнер Qdrant.

## Что хранится где

- `data/corpus.sqlite3` — исходные статьи и состояние скрапера. Подготовка и индексатор открывают базу только на чтение.
- Docker volume `qdrant_storage` внутри проекта Compose — серверный поисковый индекс.
- `data/qdrant/` — прежнее встроенное хранилище, если оно было создано. Его формат нельзя напрямую подставить как папку данных серверного Qdrant.
- `models/` — только локальный токенизатор, без весов Gemma.
- Git — код, зависимости, Compose и инструкции.

При смене встроенного режима на серверный данные сами не переносятся. Если индекс уже построен, векторы можно скопировать через API клиентов без повторного обращения к MWS; такой перенос пока не реализован. Пока индекс не построен, следует сразу начинать индексацию с адресом серверного Qdrant.

## Проверки и следующие шаги

Обычные тесты не используют MWS и не требуют Docker:

```bash
python -m unittest discover -s tests -t . -v
```

Отдельный тест HTTP-подключения использует только синтетические данные, создаёт временную коллекцию и удаляет её после проверки:

```bash
QDRANT_TEST_URL=http://127.0.0.1:6333 python -m unittest discover -s tests -t . -p test_qdrant_server.py -v
```

Для защищённого тестового сервера поддерживается `QDRANT_TEST_API_KEY`. Производственные коллекции тест не использует.

Основной поиск использует векторы Gemma в Qdrant. В проверенном индексе 500 статей и 2571 фрагмент. На dev-наборе из 32 запросов к восьми статьям получены Hit@5 = 100% и MRR@5 = 1.0. На отложенном наборе из 16 запросов к четырём другим статьям — Hit@5 = 100% и MRR@5 = 0.8594. Эти небольшие наборы не дают оценки качества на всём Хабре.

Триграммы и опечаточник находятся в `habr_search/retrieval/`, [инструкция](evaluation/SPELLING.md). На странице однозначные исправления применяются автоматически; можно повторить поиск исходной фразы. На 30 контрольных запросах полностью исправлены 12 из 20 ошибок и сохранены все 10 правильных запросов. Сравнение поисковой выдачи с исправлениями и без них ещё не выполнено ([порядок проверки](evaluation/SPELLING_BENCHMARK.md)). Отдельного словаря синонимов пока нет.

Что предстоит доработать:

- сохранить корпоративные ссылки в скрапере и обработать перенаправления внутри Хабра;
- защитить названия технологий от ложных автоматических замен;
- проверять версию содержимого индекса при загрузке словаря: сейчас сверяются только имя коллекции и число точек;
- расширить независимую разметку, добавить запросы без подходящего ответа и измерить задержку и расход API.
