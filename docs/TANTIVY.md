# Локальный поиск Tantivy

Tantivy — библиотека на Rust с готовой Python-обвязкой. Она строит обратный индекс слов и ранжирует совпадения по BM25. Поиск работает на компьютере, без MWS и Qdrant. Основной семантический режим использует BGE-M3. Gemma сохранена только для явного сравнения.

## Подготовка и запуск

Из папки проекта обновите зависимости и один раз постройте индекс из существующего корпуса:

```bash
python -m pip install -r requirements.txt
python -m habr_search.retrieval.tantivy_index build
./run.sh --engine tantivy
```

Если индекс уже построен, запускайте только последнюю команду. Откройте http://127.0.0.1:8000. Остановка — Ctrl+C. Для другого порта добавьте `--port 8001`.

При интеграции индекс для имеющихся 2665 статей уже создан в `data/tantivy/`. Это локальные данные, они не попадут в Git.

Прямой запуск и консольный поиск:

```bash
python -m habr_search.web.app --engine tantivy
python -m habr_search.retrieval.tantivy_index search --query "автоматизация документов"
```

Вернуться к прежнему поиску через MWS:

```bash
./run.sh --engine gemma
```

## Что хранится и как выполняется поиск

- `data/corpus.sqlite3` — исходные статьи. Построение читает базу, не меняя её.
- `data/tantivy/` — индекс целых статей: идентификатор, заголовок, текст и ссылка. Фрагменты Gemma для этого не нужны.
- `data/tantivy/manifest.json` — версия формата, число статей и отпечаток содержимого. Это небольшой служебный файл, не копия корпуса.
- `data/tantivy/spelling.sqlite3` — словарь опечаток из тех же статей, связанный с версией локального индекса.

Слова приводятся к нижнему регистру, ё сопоставляется с е, русский стеммер убирает окончания. Запрос ищется по заголовку и полному тексту; вес заголовка — 3, текста — 1. Учитывается совпадение хотя бы одного слова. Пунктуация разделяет слова, пользовательские операторы поискового языка не выполняются. Максимум — 4000 символов, 64 разных слова по 80 символов.

Отрывок выбирает Tantivy рядом с совпадением, в браузер передаётся обычный текст. Выдача содержит до 20 разных статей, кнопка «Показать ещё» раскрывает её по пять.

Введённый запрос не исправляется автоматически. Страница сначала получает результаты, затем отдельно запрашивает опечаточник и показывает «Возможно, вы имели в виду». Устаревший ответ подсказки не заменяет предложение для нового запроса. `--without-spelling` отключает подсказки. Для Tantivy используется собственный словарь внутри папки индекса, параметр `--spelling-db` относится к семантическим режимам.

Оценка BM25 не является процентом и не сравнивается с косинусным сходством Gemma. Параметры `--min-score`, `--raw-query` и подключения Qdrant относятся к семантическим режимам. Локальный режим не использует модель для синонимов и перефразировок.

## Обновление корпуса

Существующая папка индекса не перезаписывается. После добавления статей постройте новую версию и перезапустите сервер с её путём:

```bash
python -m habr_search.retrieval.tantivy_index build --index-path data/tantivy-v2
./run.sh --engine tantivy --tantivy-path data/tantivy-v2
```

Для консольного поиска и оценки этот же путь указывается через `--index-path`. Индекс и словарь публикуются вместе после успешной сборки. Запущенный сервер использует снимок и не перечитывает изменённый корпус автоматически.

## Проверка качества

```bash
python -m habr_search.evaluation.evaluate_tantivy
```

Команда проверяет исходные запросы из `evaluation/benchmark_dev.csv`, без исправлений опечаток, и сохраняет новый CSV в `data/evaluation/`. Можно задать `--queries`, `--top-k` и `--output`; существующий отчёт не перезаписывается. Отчёт имеет отдельный формат с BM25 и не предназначен для калибровки косинусного порога Gemma.

Первый прогон 24 октября 2026 года: 2665 статей, 40 запросов, из них 36 с ожидаемыми статьями. Hit@5 — 26/36 (72,22%), MRR@5 — 0,6389; медиана — 15 мс, p95 — 25 мс. Измерен локальный поиск с отрывками, без HTTP, загрузки сервиса и расчёта подсказок. На всех четырёх запросах без ожидаемого ответа выдача осталась непустой.

Для сравнения, прежний сохранённый результат Gemma на полном корпусе: Hit@5 — 35/36 (97,22%), MRR@5 — 0,9167, медиана — 299 мс, p95 — 384 мс. Это историческое измерение другого режима, а не одновременный тест. Контрольный набор небольшой; эти числа не гарантируют качество на произвольных запросах. Holdout при интеграции не использовался.

Вывод: локальный поиск быстрее, но хуже понимает перефразировки и синонимы. Для следующего сравнения можно подключить более лёгкую модель на MWS; текущая модель и векторный индекс пока не менялись.

## Где смотреть код

- `habr_search/retrieval/tantivy_index.py` — сборка, анализ слов, поиск и отрывки.
- `habr_search/web/app.py`, класс `TantivyService` — подключение к общему API.
- `habr_search/web/static/app.js` — выдача и отдельная загрузка подсказки.
- `habr_search/evaluation/evaluate_tantivy.py` — метрики и CSV.
- `tests/test_tantivy.py` — проверки настоящего индекса на временном корпусе.

Используется `tantivy==0.26.0`, совместимый с Python 3.10. Официальные источники: [Python-обвязка](https://github.com/quickwit-oss/tantivy-py), [API](https://tantivy-py.readthedocs.io/en/latest/api/tantivy/tantivy.html).
