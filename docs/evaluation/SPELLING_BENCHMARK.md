# Проверка опечаточника на 30 запросах

`spelling_queries.csv` содержит 20 запросов с ошибками и 10 правильных. Для каждого записаны исходный текст, желаемый текст после исправления и известные подходящие статьи. Эталон означает желаемое поведение, а не фактический ответ текущего алгоритма. В набор намеренно включены случаи, которые алгоритм пока не поддерживает.

Проверяются пропуски, лишние буквы, замены, соседние перестановки, две правки, заглавные названия, неверная раскладка, раздельное и слитное написание, а также ошибка, образующая другое известное слово. Правильные запросы содержат технические названия и сокращения. Это небольшой набор для разработки по знакомым темам, не независимый итоговый экзамен и не исчерпывающая разметка релевантности. Несколько проверок относятся к одним и тем же статьям.

Темы и ожидаемые статьи взяты из существующих наборов `queries.csv` и `queries_dev.csv`: создание отчётов Word, Joomla, Ktor, FreePBX, YDB, WordPress, экспорт PDF, закон Амдала и LumaBloom. Новые формулировки сохраняют исходную задачу, кроме намеренных ошибок. Ожидаемых статей может быть несколько; другая полезная статья в выдаче может оказаться неразмеченной. Старый `queries_holdout.csv` не использовался для выбора правил или составления новых ошибок.

## Локальная оценка

```bash
python -m habr_search.evaluation.evaluate_spelling local --output-dir data/evaluation/spelling-baseline
```

Команда не использует MWS, токенизатор или Qdrant. Читается существующий словарь `data/spelling-bge-m3.sqlite3`; иной путь задаётся через `--dictionary`. Новая папка содержит:

- `local.csv` — ожидаемое и фактическое исправление, признак полного совпадения и изменения, отпечатки словаря, правил и набора, имя коллекции и число точек;
- `original.csv` — исходные запросы в формате `habr_search/evaluation/evaluate.py`;
- `corrected.csv` — реально применённые исправления с теми же id и ожидаемыми статьями.

В `corrected.csv` попадает ответ алгоритма, а не эталон. Неподдержанные опечатки остаются в нём неисправленными. Существующая папка не перезаписывается; для повторной проверки задайте другое имя или пропустите `--output-dir`, чтобы получить имя по времени UTC. Исходная разметка не изменяется.

На словаре из 500 статей и 2571 фрагмента получено:

| Показатель | Результат |
|---|---:|
| запросов с опечатками полностью исправлено | 12/20 (60%) |
| правильных запросов изменено | 0/10 |

Не исправлены две правки в слове, заглавное название внутри фразы, внутренние заглавные буквы, аббревиатура, неверная раскладка, разорванное и слитное слово, ошибка с другим известным словом. Правила не подгонялись под этот результат. Отсутствие ошибочных замен на десяти примерах не доказывает безопасность всех исправлений.

## Проверка влияния на поиск

Следующие две команды пользователь запускает с ключом MWS. Это по 30 обращений на полный запуск с нуля, всего 60. Индекс статей не пересчитывается.

```bash
python -m habr_search.evaluation.evaluate --queries data/evaluation/spelling-baseline/original.csv \
  --qdrant-url http://127.0.0.1:6333 --timeout 300 \
  --output data/evaluation/spelling-baseline/original-search.csv

python -m habr_search.evaluation.evaluate --queries data/evaluation/spelling-baseline/corrected.csv \
  --qdrant-url http://127.0.0.1:6333 --timeout 300 \
  --output data/evaluation/spelling-baseline/corrected-search.csv
```

При остановке используйте `--resume` с частичным отчётом именно своего набора и новый свободный путь `--output`. Не передавайте исходный отчёт как продолжение исправленного. Во время сравнения не меняйте индекс.

После двух полностью завершённых запусков сравнить готовые CSV без MWS:

```bash
python -m habr_search.evaluation.evaluate_spelling compare \
  --original-queries data/evaluation/spelling-baseline/original.csv \
  --corrected-queries data/evaluation/spelling-baseline/corrected.csv \
  --original-report data/evaluation/spelling-baseline/original-search.csv \
  --corrected-report data/evaluation/spelling-baseline/corrected-search.csv
```

Команда проверяет строки отчётов, совпадение id, категорий и ожидаемых статей, коллекции, числа точек, версии содержимого, инструкции и `top_k`. Неполные отчёты отклоняются. Выводятся Hit@k, MRR@k и запросы с улучшившимся или ухудшившимся местом. Версия содержимого меняется нашим индексатором до записи точек. При ручном изменении Qdrant нужно также обновлять версию коллекции. Старые отчёты без версии не принимаются. До выполнения этих запусков измерена только точность изменения текста, не улучшение поиска.
