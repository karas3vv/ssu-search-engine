# Контрольные запросы для поиска

`queries.csv` содержит 18 стартовых проверок по шести статьям, которые уже встречались в выдаче на корпусе из 100 статей. Набор подготовлен по заголовкам, показанным отрывкам и выполненным вручную поисковым запросам. Разметка предварительная и неполная: её нужно сверить с полными текстами и расширить статьями из других тем.

Это проверки работоспособности и начальное сравнение вариантов поиска. Несколько формулировок относятся к одной статье, а темы сосредоточены вокруг офисной автоматизации. Итоговые результаты нельзя переносить на весь Хабр. После настройки алгоритмов потребуется отдельный набор запросов, который не использовался при настройке.

## Формат набора

Все команды выполняются из корня проекта. CSV хранится в UTF-8 и редактируется обычным текстовым редактором:

```csv
query_id,category,query,relevant_article_ids
positions_exact,exact,Как автоматически заполнять должности сотрудников в Excel?,891074
```

- `query_id` — уникальное имя проверки латиницей, цифрами и символами `_` или `-`.
- `category` — группа: `exact` для прямых запросов, `paraphrase` для перефразировок, `alias` для вариантов названий, `typo` для опечаток. Можно добавлять свои группы.
- `query` — текст запроса.
- `relevant_article_ids` — хотя бы один id ожидаемой статьи; категория `no_answer` требует пустого поля. Несколько id разделяются `;`: например, `795057;888510`.

В наборе отмечены известные подходящие статьи, а не все возможные релевантные результаты. Неотмеченная статья тоже может оказаться полезной. Все перечисленные id должны присутствовать в индексе; при отсутствии хотя бы одного скрипт останавливается до обращения к MWS. Триграммы и исправление опечаток реализованы отдельно; [подготовка исправленной копии запросов и сравнение](SPELLING.md). Синонимы ещё не реализованы. Категории запросов позволяют сравнивать влияние этих изменений.

Первые три строки повторяют уже проверенные запросы к статьям:

- `795057` и `888510` — создание документов Word с использованием данных Excel и Python;
- `891074` — должности сотрудников в Excel;
- `575278` — Power Automate Desktop.

Остальные проверки также используют `717902` (ExecuteExcel4Macro) и `821879` (Python in Excel).

## Запуск

Проверка структуры CSV без Qdrant, MWS, скачивания токенизатора и создания отчёта:

```bash
python -m habr_search.evaluation.evaluate --dry-run
```

Этот режим не проверяет наличие статей в индексе и длину входа для модели.

Пробная оценка первых трёх запросов на существующем серверном индексе:

```bash
python -m habr_search.evaluation.evaluate --limit 3 --qdrant-url http://127.0.0.1:6333
```

Весь набор:

```bash
python -m habr_search.evaluation.evaluate --qdrant-url http://127.0.0.1:6333
```

Ключ вводится один раз или берётся из `MWS_API_KEY`. Затем выполняется по одному обращению к MWS для каждого ещё не выполненного запроса: при запуске с нуля это 3 обращения для `--limit 3` или 18 для полного набора. Без `--resume` повторный запуск снова получает все выбранные векторы запросов. Векторы статей не пересчитываются, SQLite не читается, поисковый индекс не изменяется.

По умолчанию `habr_search/evaluation/evaluate.py` ждёт данные ответа MWS до 300 секунд. Настройка `--timeout 420` увеличивает этот интервал; также принимается имя `--timeout-seconds`. Тайм-аут подключения остаётся 10 секунд. Это ограничение ожидания данных, а не обещание завершить весь запуск за указанное время. `habr_search/ingestion/index.py` также поддерживает `--timeout` с исходным значением 300 секунд; остальные команды сохраняют прежние настройки ожидания. При тайм-ауте сообщение содержит имя запроса. Ошибки подключения и ожидания данных ответа различаются и показывают соответствующий лимит. Автоматических повторов нет: после обрыва ожидания сервер мог уже обработать запрос.

Параметры `--max-tokens`, `--overlap-tokens`, адрес MWS и деплоймент должны совпадать с индексацией. `--raw-query` выбирается так же, как в `habr_search/retrieval/search.py`: только если сервер сам добавляет инструкцию Gemma. Перед вводом ключа проверяются коллекция, ожидаемые статьи и длины всех выбранных запросов вместе с инструкцией.

## Метрики

Оцениваются разные статьи, сгруппированные через тот же `search_articles`, что использует `habr_search/retrieval/search.py`. По умолчанию `k = 5`, его можно изменить через `--top-k`.

- **Hit@k** — доля запросов, у которых хотя бы одна отмеченная подходящая статья найдена в первых `k` результатах. Эта метрика также называется Success@k.
- **MRR@k** — среднее обратное место первой отмеченной подходящей статьи: место 1 даёт `1`, место 2 — `0.5`, место 5 — `0.2`. Если статья не найдена в первых `k`, вклад равен `0`.

Например, для мест `1`, `2` и пропуска Hit@5 равен `2/3`, а MRR@5 равен `(1 + 0.5 + 0)/3 = 0.5`. При нескольких подходящих статьях достаточно первой. Hit и MRR рассчитываются только для положительных запросов. Для `no_answer` отдельно считаются пустые и непустые выдачи. Сводка выводится для всего набора и отдельно по категориям. Precision@k и Recall@k пока не рассчитываются: для содержательной оценки нужна более полная разметка релевантности.

Определения: [Success](https://ir-measur.es/en/latest/measures.html#success), [Reciprocal Rank](https://ir-measur.es/en/latest/measures.html#rr) в документации ir-measures. Дополнительная библиотека для расчёта этих двух метрик не нужна.

## Отчёт и сопоставимость запусков

CSV-отчёт сохраняется в `data/evaluation/results-<время UTC>.csv` и исключён из Git вместе с `data/`. Для собственного пути используйте `--output путь.csv`; существующий файл не перезаписывается.

Для каждого запроса записываются время начала, имя коллекции, число фрагментов, версия содержимого индекса, длительность запроса, хеш выбранного набора запросов, режим инструкции, `top_k`, ожидаемые и найденные id, место и обратное место. Один и тот же хеш означает одинаковые выбранные запросы и разметку в одинаковом порядке.

Каждая завершённая проверка сразу сохраняется в отчёт. При ошибке или остановке файл может быть неполным; итоговые метрики для неполного запуска не выводятся.

Чтобы продолжить после сбоя, укажите последний частичный отчёт:

```bash
python -m habr_search.evaluation.evaluate --qdrant-url http://127.0.0.1:6333 --timeout 300 \
  --resume data/evaluation/benchmark-dev-partial.csv
```

Замените имя файла своим. Скрипт проверяет совместимость сохранённых строк с текущими запросами, разметкой, коллекцией, числом фрагментов, версией содержимого индекса, `top_k` и режимом инструкции. Повреждённые строки, повторные id и несоответствие места найденной выдаче отклоняются. Пустой отчёт с корректным заголовком допускается: в нём ещё нечего повторно использовать.

Завершённые проверки копируются в **новый** отчёт вместе с их исходным временем. Для них запросы в MWS не отправляются. Затем выполняются оставшиеся проверки, а итоговые метрики учитывают весь выбранный набор. Исходный файл сохраняется без изменений; новый путь можно задать через `--output`. Если новый запуск тоже прервётся, в следующий раз укажите уже его отчёт. Когда все проверки были завершены ранее, метрики пересчитываются без MWS и ввода ключа.

Для продолжения нужен тот же выбранный набор: нельзя продолжить отчёт с `--limit 3` как полный набор из 18 запросов. При изменении набора, разметки или настроек поиска начните новую оценку. Тайм-аут можно менять между продолжениями. `--dry-run` проверяет только исходный CSV запросов, а не совместимость отчёта `--resume`.

Во время оценки не обновляйте индекс. Изменение числа фрагментов обнаруживается проверкой в конце запуска; замена текстов и векторов с сохранением их количества этой проверкой не выявляется. При сравнении вариантов семантического поиска используйте одинаковый состав статей, тот же набор запросов и тот же `top_k`.


## Расширенные наборы

Стартовый `queries.csv` и связанные с ним отчёты сохранены. Для расширения индекса подготовлены `queries_dev.csv` (32 запроса по восьми статьям) и `queries_holdout.csv` (16 запросов по четырём другим статьям). Основания разметки по полным текстам, разделение наборов и команды описаны в [EXPANDED.md](EXPANDED.md). Новые наборы передаются существующим командам через `--queries`.

Новые отчёты содержат `index_revision` и `elapsed_ms`. Старые CSV без этих столбцов сохраняются, но не подходят для нового `--resume`. Расширенный набор из 80 запросов, ограничения отрицательной разметки и подготовка таблицы ручной проверки описаны в [BENCHMARK.md](BENCHMARK.md).
