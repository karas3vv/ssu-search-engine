# Страница и API поиска

`habr_search/web/app.py` запускает локальное приложение FastAPI. Оно использует те же `search_articles`, инструкцию Gemma, токенизатор и коллекцию, что и консольный поиск. Подключения и словарь загружаются один раз, а запросы обслуживаются последовательно. Страница в `habr_search/web/static/` работает без Node.js, сборки и внешних шрифтов или скриптов.

## Запуск

Из папки проекта обновите зависимости:

```bash
python -m pip install -r requirements.txt
```

Запустите существующий Qdrant, если он остановлен:

```bash
docker compose up -d qdrant
```

Затем:

```bash
python -m habr_search.web.app --qdrant-url http://127.0.0.1:6333 --timeout 300
```

Ключ MWS берётся из `MWS_API_KEY` или один раз вводится скрыто в терминале. Он хранится в памяти процесса, не передаётся странице и не записывается в код, файлы или журналы приложения. Откройте [страницу поиска](http://127.0.0.1:8000). Справочник запросов API доступен по [адресу /docs](http://127.0.0.1:8000/docs). Остановка — `Ctrl+C` в терминале сервера.

Клиент модели создаётся при запуске, но обращение к MWS происходит только при поиске. Открытие страницы, примеры запросов и чтение сведений о корпусе модель не вызывают. В пустом поле показывается случайный пример запроса, который меняется раз в шесть секунд. При фокусе, вводе текста, поиске и в скрытой вкладке смена приостанавливается. Если пользователь предпочитает уменьшенное движение, остаётся один случайный пример. Подсказка не подставляется в текст запроса и не отправляется в поиск. Кнопка с примером под строкой заполняет поле; для поиска нужно нажать «Найти» или Enter. Поиск выполняется по введённой фразе.

Если есть подходящее исправление, появляется «Возможно, вы имели в виду: …». Нажатие подставляет предложенный текст в поле и запускает новый поиск. До нажатия запрос не меняется и второго обращения к модели нет. Неоднозначные слова без подходящего варианта целой фразы не дают отдельной подсказки.

В карточках показаны заголовок, ссылка и подходящий отрывок, в шапке — число статей. Сходство и время обработки остаются в API для измерений.

## Параметры

- `--port 8001` — другой локальный порт;
- `--spelling-db data/spelling-next.sqlite3` — другой заранее построенный словарь;
- `--without-spelling` — запуск без словаря и исправлений;
- `--tokenizer-file путь/tokenizer.json` — локальный токенизатор Gemma;
- `--max-tokens`, `--overlap-tokens`, `--raw-query` — как в `habr_search/retrieval/search.py`, должны соответствовать индексу и настройке сервера модели;
- `--qdrant-path` — встроенный режим вместо сервера; другим командам нельзя открывать эту папку одновременно.

Словарь по умолчанию нужен в `data/spelling.sqlite3`; его можно построить через `python -m habr_search.retrieval.spellcheck build`. При несовпадении версии индекса словарь отключается; пересоберите его и перезапустите приложение. Старый формат словаря также не даёт подсказок; [переход на новый формат](evaluation/SPELLING.md). Число статей в шапке — снимок на момент запуска приложения.

## API

| Метод и путь | Назначение | MWS |
|---|---|---|
| `GET /api/health` | коллекция, число фрагментов и статей при запуске, наличие словаря | нет |
| `POST /api/suggest` | предложение исправления и варианты | нет |
| `POST /api/search` | семантическая выдача, до 20 разных статей | одно обращение |

Пример тела запроса поиска:

```json
{"query": "автоматизаця документов", "top_k": 5, "correct_typos": false}
```

В API параметр `correct_typos` по-прежнему управляется явно и по умолчанию равен `false`, чтобы сохранять возможность экспериментов. Браузер всегда отправляет `false` и использует поле ответа `suggested_query` для отдельной кнопки. После нажатия выбранный текст передаётся как новый запрос, также с `false`. `true` оставлен как явная возможность API для экспериментов. `POST /api/suggest` принимает только `query`. Запросы должны иметь `Content-Type: application/json`. Неизвестные поля, строки вместо чисел и строковые флаги отклоняются. Пустой запрос или превышение 1024 токенов вместе с инструкцией не отправляются в модель.

Сервер слушает только `127.0.0.1`; это локальный интерфейс без пользовательских аккаунтов. Запросы из браузера с чужим Origin и неизвестным Host отклоняются. Параллельный поиск получает HTTP 429 до обращения в MWS. Ошибка модели возвращает HTTP 502, недоступность Qdrant — 503. Повторов запросов автоматически нет; закрытие вкладки не гарантирует отмену уже отправленного запроса модели.

Жизненный цикл подключения, раздача файлов и HTTP-проверки следуют документации FastAPI: [lifespan](https://fastapi.tiangolo.com/advanced/events/), [static files](https://fastapi.tiangolo.com/tutorial/static-files/), [testing](https://fastapi.tiangolo.com/tutorial/testing/).
