# Подключение BGE-M3 на MWS

Профиль `bge-m3` использует деплоймент `bge-m3` по адресу `https://gpt.mwsapis.ru/projects/habr-parser/openai/v1/embeddings`. Вычисление эмбеддингов выполняет MWS; на компьютер загружается только токенизатор, без весов модели.

Корпус SQLite и индекс Tantivy остаются прежними. BGE-M3 получает отдельную коллекцию Qdrant с префиксом `habr_bge_m3_`. Векторы Gemma не копируются и не преобразуются: эмбеддинги статей необходимо вычислить новой моделью. Gemma сохранена для сравнения; её коллекция и идентификаторы фрагментов не изменены.

## 1. Проверить настройки

Команды выполняются из папки проекта с установленными зависимостями. Для выбора модели в командах индексации, поиска, проверки API и оценки используется `--embedding-model bge-m3`; в веб-приложении — `--engine bge-m3`.

Если раньше переменная `MWS_EMBEDDINGS_MODEL` указывала на `parser`, измените её в текущем терминале:

```bash
export MWS_EMBEDDINGS_MODEL=bge-m3
```

При отсутствии переменной профиль сам выбирает `bge-m3`. `MWS_EMBEDDINGS_URL` также может переопределить адрес; для указанного проекта менять его не требуется. Ключ не сохраняется в проект: он запрашивается скрыто в терминале или читается из `MWS_API_KEY`.

Сначала можно бесплатно проверить нарезку пяти статей:

```bash
python -m habr_search.ingestion.index --embedding-model bge-m3 --limit 5 --dry-run
```

При первом запуске скачивается только публичный `tokenizer.json`. Эта команда не вызывает MWS, не подключается к Qdrant и не записывает векторы. На текущих первых пяти статьях получено 18 фрагментов, максимальная длина — 1012/1024 токенов.

## 2. Проверить API на одном тексте

Эта команда делает **один запрос к MWS**:

```bash
python -m habr_search.embeddings --embedding-model bge-m3
```

Ожидаются деплоймент `bge-m3` и размерность 1024. Если размерность отличается, команда сообщит об ошибке. Это проверка подключения, корпус при ней не индексируется.

## 3. Проиндексировать пять статей для пробы

Сначала запустите Qdrant, затем индексатор. Индексатор вызывает MWS и расходует средства по тарифу сервиса:

```bash
docker compose up -d qdrant
python -m habr_search.ingestion.index --embedding-model bge-m3 \
  --qdrant-url http://127.0.0.1:6333 --limit 5 --timeout 300
```

Проверить поиск по пробной коллекции можно так:

```bash
python -m habr_search.retrieval.search --embedding-model bge-m3 \
  --qdrant-url http://127.0.0.1:6333 --query "автоматизация документов"
```

Каждый семантический поиск вызывает модель один раз. Для запуска страницы по пяти статьям словарь пока можно отключить:

```bash
./run.sh --engine bge-m3 --without-spelling
```

Откройте http://127.0.0.1:8000. Если порт занят другим сервером, остановите тот сервер через Ctrl+C или добавьте `--port 8001`. Открытие страницы не вызывает MWS.

## 4. Продолжить на полном корпусе

После успешной пробы увеличьте общий лимит до числа статей в корпусе:

```bash
python -m habr_search.ingestion.index --embedding-model bge-m3 \
  --qdrant-url http://127.0.0.1:6333 --limit 2665 --timeout 300
```

Лимит включает уже записанные статьи. Повторный запуск с теми же настройками пропустит готовые точки без повторного вычисления эмбеддингов. Для остановки используйте Ctrl+C; для продолжения повторите ту же команду. Все новые фрагменты всё равно требуют расчёта в MWS. Автоматических повторов при сбое API нет.

После окончания создайте отдельный словарь и запустите страницу:

```bash
python -m habr_search.retrieval.spellcheck build --embedding-model bge-m3 \
  --qdrant-url http://127.0.0.1:6333
./run.sh --engine bge-m3
```

Словарь сохраняется в `data/spelling-bge-m3.sqlite3`; построение не вызывает модель. Если такой файл уже существует, он не перезаписывается: для обновлённого индекса задайте новый `--dictionary` и передайте его серверу через `--spelling-db`.

## 5. Сравнить качество и время

Когда в коллекции есть все ожидаемые статьи, выполните оценку на том же наборе:

```bash
python -m habr_search.evaluation.evaluate --embedding-model bge-m3 \
  --qdrant-url http://127.0.0.1:6333 --queries evaluation/benchmark_dev.csv --timeout 300
```

Каждый контрольный запрос получает эмбеддинг через MWS. Новый CSV появится в `data/evaluation/`, старые отчёты не заменяются. Для продолжения прерванной оценки передайте её CSV через `--resume`; отчёт Gemma с другой коллекцией использовать для продолжения нельзя.

Сравнивайте Hit@5, MRR@5 и время на одинаковых запросах и полном корпусе. Маленькая модель не гарантирует низкую задержку сервера или сохранение качества. Порог сходства Gemma переносить на BGE-M3 без проверки нельзя.

## Что поменялось в коде

- `habr_search/model_profiles.py` — единый профиль: модель, деплоймент, размерность, ревизия токенизатора, специальные токены и инструкция запроса.
- `habr_search/ingestion/chunking.py` — выбирает токенизатор и учитывает профиль при вычислении стабильных идентификаторов.
- `habr_search/ingestion/index.py` — создаёт коллекцию с 1024 координатами и записывает правильные сведения о модели в payload.
- `habr_search/retrieval/search.py` — отправляет запрос BGE-M3 обычным текстом, без инструкции Gemma.
- `habr_search/evaluation/evaluate.py`, `retrieval/spellcheck.py`, `web/app.py` — используют ту же коллекцию и профиль.
- `habr_search/embeddings.py` — проверяет выбранный деплоймент и размерность при пробе API.
- `tests/test_model_profiles.py` — автономные проверки токенизации, размерности, возобновления и всех команд без реальных запросов MWS.

Используется dense-вектор BGE-M3 из стандартного ответа `/embeddings`. Sparse- и ColBERT-представления не включаются автоматически. Хотя модель поддерживает вход до 8192 токенов, для этого подключения оставлены фрагменты до 1024 с перекрытием 128 и запросы до 1024 токенов. Фактический лимит сервера может быть ниже максимума модели.

Параметры модели и отсутствие обязательной инструкции: [карточка BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3). Токенизатор закреплён на ревизии `5617a9f61b028005a4858fdac845db406aefb181`.
