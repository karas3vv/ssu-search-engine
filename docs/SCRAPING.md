# Сбор статей

Скрапер сохраняет полный текст и метаданные в `data/corpus.sqlite3`. Таблица `queue` хранит ссылки и прогресс обхода. При обычном сборе JSONL не создаётся: подготовка и индексация читают SQLite напрямую.

Запуск из корня проекта:

```bash
python -m habr_search.ingestion.scrape --limit 4000
```

`--limit` задаёт общее число статей с учётом уже сохранённых. При остановке повторите ту же команду. Сервер Qdrant и ключ MWS для сбора не нужны.

## Ранее пропущенные статьи компаний

Старая версия заменяла корпоративные ссылки на `/ru/articles/id/`, а переход на правильный адрес считала ошибкой. Эти статьи оставались в очереди со статусом `failed` и не скачивались.

```bash
python -m habr_search.ingestion.scrape --limit 4000 --retry-redirects
```

Флаг возвращает в очередь только старые ошибки перенаправления на ту же статью Хабра. Другие ошибки не сбрасываются. Уже сохранённые документы не перезаписываются. Это обычный запуск сбора: кроме восстановленных задач обрабатываются и остальные ожидающие ссылки, пока не достигнут общий лимит.

Пути статей компаний сохраняются. Скрапер следует не более чем пяти переходам, проверяет HTTPS, домен, id статьи и robots.txt перед каждым запросом. Пауза между запросами сохраняется и при перенаправлении.

Добавление статей в SQLite само по себе не обновляет Qdrant. Индексация и пересборка словаря выполняются отдельно; они описаны в [инструкции по индексации](evaluation/EXPANDED.md) и [инструкции по словарю](evaluation/SPELLING.md).

## Экспорт по необходимости

Если статьи нужны другой программе в формате JSONL, создайте выгрузку явно:

```bash
python -m habr_search.ingestion.scrape --export-only
```

Команда записывает `data/articles.jsonl` из текущего корпуса без обращений к Хабру и MWS. Существующая выгрузка заменяется. Обычный сбор не создаёт и не обновляет этот файл, поэтому после добавления статей для актуальной выгрузки повторите команду экспорта.
