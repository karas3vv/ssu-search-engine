# поиск по статьям хабра

Исходные статьи хранятся в `data/corpus.sqlite3`. Существующий `articles.jsonl` можно оставить как выгрузку. Подготовка и разбиение работают в памяти и не меняют корпус.

## установка

Нужен Python 3.10 или новее. Из папки проекта:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## что делает код

- `scrape.py` — собирает статьи и хранит очередь загрузки. Повторный сбор сейчас не нужен.
- `prepare.py` — проверяет поля, очищает управляющие символы и пропускает полные дубли текста. `PreparedArticle` описывает статью, `PreparationStats` собирает счётчики. `cast` уточняет тип для анализатора; значения всё равно проверяются при выполнении.
- `chunking.py` — делит подготовленные статьи на фрагменты. `ArticleChunk` содержит текст, ссылку, ID статьи и вход для модели. `start_char` и `end_char` задают срез подготовленного текста, `token_count` учитывает заголовок, префикс и специальные токены.

Проверить корпус:

```bash
python prepare.py
```

Посмотреть разбиение пяти статей:

```bash
python chunking.py --limit 5 --preview 2
```

Проверить разбиение ста статей без вывода текстов:

```bash
python chunking.py --limit 100 --preview 0
```

При первом запуске `chunking.py` скачивает **только файл токенизатора** в `models/`. Затем работает с локальной копией. Веса модели, эмбеддинги и Qdrant на этом этапе не нужны. Вариант `--tokenizer-file /путь/tokenizer.json` позволяет указать уже загруженный токенизатор этой же модели.

## разбиение для удалённой gemma

`chunking.py` использует токенизатор `BAAI/bge-multilingual-gemma2`, версия `8365500e19bc804136f4ad12c2494430239a2d72`. Документы для этой модели передаются обычным текстом, без префикса E5 `passage: `. [Описание модели](https://huggingface.co/BAAI/bge-multilingual-gemma2#usage).

По умолчанию весь вход ограничен 1024 токенами, а соседние фрагменты перекрываются на 128 токенов исходного текста. В подсчёт входят заголовок и специальные токены `<bos>` и `<eos>`. Заголовок добавляется в каждый вход; слишком длинный заголовок сокращается только во входе модели. Срезы сохраняют исходные символы и отступы, границы по возможности выбираются на переносах строк. Один длинный абзац разбивается по токенам. Стабильный UUID зависит от статьи, содержимого, версии модели и настроек разбиения.

Размер фрагмента и перекрытие можно менять:

```bash
python chunking.py --limit 5 --max-tokens 1024 --overlap-tokens 128 --preview 2
```

Конфигурация самой модели допускает до 8192 токенов, но лимит удалённого деплоймента нужно уточнять отдельно. Значение 1024 выбрано как стартовая настройка для проверки качества, а не как максимальная длина статьи. Старый токенизатор E5 не подходит; модуль проверяет специальные токены при загрузке файла.

Текущие данные уже извлечены из HTML: подготовка сохраняет имеющиеся отступы, но не восстанавливает форматирование, потерянное при скачивании.

## проверка

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют покрытие текста без пропусков, лимиты, перекрытие, стабильность ID и сохранение отступов. Для тестов интернет не нужен.

Для проверки типов можно установить зависимости разработки:

```bash
python -m pip install -r requirements-dev.txt
python -m mypy --strict prepare.py chunking.py embeddings.py tests
python -m pyright prepare.py chunking.py embeddings.py tests
```

В редакторе нужно выбрать интерпретатор `.venv`, в который установлены зависимости.

## проверка удалённой модели mws

`chunking.py` адаптирован под `BAAI/bge-multilingual-gemma2`, которую планируется использовать на сервере. В запросах MWS поле `model` содержит имя деплоймента `parser`. Само это имя не подтверждает базовую модель: её нужно проверить в настройках деплоймента в консоли MWS.

`embeddings.py` — отдельный клиент для проверки API. Он отправляет только указанный тестовый текст и не читает корпус. Запустите в терминале из папки проекта:

```bash
python embeddings.py --text "Привет, как дела?"
```

Если переменная окружения `MWS_API_KEY` не задана, программа попросит API-ключ сервисного аккаунта через скрытый ввод. Вводимые символы не отображаются; ключ в файл не записывается. Ключ нужно вводить в терминале, не отправлять в чат и не добавлять в исходный код.

По умолчанию используются:

- адрес: `https://gpt.mwsapis.ru/projects/habr-parser/openai/v1/embeddings`;
- деплоймент: `parser`;
- переменная с ключом: `MWS_API_KEY`.

Адрес и деплоймент можно переопределить через `MWS_EMBEDDINGS_URL` и `MWS_EMBEDDINGS_MODEL`. Сервисному аккаунту нужна роль `gpt.inferencer`. Формат запросов и ответов описан в [документации MWS](https://mws.ru/docs/cloud-platform/gpt/general/inference-text.html).

При успехе программа напечатает размерность вектора и первые пять координат. Размерность определяется по реальному ответу, а не задаётся в клиенте. Она нужна для настройки будущей коллекции Qdrant, но сама по себе не доказывает, какая модель стоит за деплойментом. Проверка соединения также не оценивает качество поиска.

Клиент принимает список строк, проверяет размерности и конечность координат и восстанавливает порядок ответов по полю `index`. Ошибки HTTP выводятся без тела ответа и ключа. Автоматических повторов запросов нет. Сам клиент не добавляет никаких модельных префиксов.

Полезные ошибки:

- `401` — проверить API-ключ;
- `403` — проверить доступ к проекту и роль сервисного аккаунта;
- `404` — проверить адрес проекта и деплоймент;
- `429` — проверить квоты и повторить позже.

Тестовый запрос и массовая обработка используют удалённый сервис. Обработка всего корпуса не запускается при проверке соединения.

Тест API уже выполнен пользователем: деплоймент `parser` вернул вектор размерности 3584. Это согласуется с выбранной Gemma, но точную базовую модель и лимит входа нужно проверить в настройках деплоймента. Локальные проверки кода не отправляют статьи в API.

Тексты фрагментов уже подготовлены в формате документов Gemma. Для будущего поиска в [примере авторов](https://huggingface.co/BAAI/bge-multilingual-gemma2#usage) запросы используют инструкцию формата `<instruct>...\n<query>...`. Нужно согласовать её с настройками сервера, чтобы не добавить инструкцию дважды. Веса модели локально скачивать не требуется; для разбиения используется только токенизатор.

## следующий шаг

Сначала проверить примеры локального разбиения и подтвердить базовую модель деплоймента `parser`. Затем написать `index.py`: передавать фрагменты удалённой модели и загружать эмбеддинги с метаданными в Qdrant. Начать с небольшой выборки статей и предусмотреть продолжение после сбоев. После этого добавить `search.py` с форматом запроса выбранной модели и объединением фрагментов одной статьи в выдаче.
