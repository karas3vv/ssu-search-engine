# Поиск по статьям Хабра

Учебный поисковый движок: находит статьи по смыслу запроса и предлагает исправления опечаток. Эмбеддинги вычисляются через MWS, индекс хранится в Qdrant. Для быстрого локального поиска добавлен отдельный режим Tantivy с обратным индексом. Доступны веб-интерфейс, API и поиск из терминала.

## Как это работает

При подготовке данных статьи Хабра сохраняются в SQLite. Тексты очищаются и разбиваются на перекрывающиеся фрагменты. Удалённая модель Gemma или BGE-M3 через MWS преобразует каждый фрагмент в числовой вектор, отражающий его смысл. Векторы, тексты и ссылки сохраняются в Qdrant.

При поиске опечаточник предлагает исправления с помощью символьных триграмм и проверки числа правок. Веб-интерфейс ищет введённую фразу и предлагает исправленный вариант, который можно выбрать нажатием. Запрос преобразуется в вектор той же моделью, а Qdrant находит близкие фрагменты. Пользователь получает список разных статей с заголовками, ссылками и подходящими отрывками. Повторно обрабатывать весь корпус для каждого запроса не нужно.

## Структура проекта

```text
habr_search/
  ingestion/    # сбор статей, очистка, разбиение и индексация
  retrieval/    # семантический поиск и опечаточник
  evaluation/   # оценка поиска и сравнение исправлений
  web/          # сервер и страница поиска в static/
  model_profiles.py # параметры Gemma и BGE-M3
  embeddings.py # клиент модели MWS
  vector_store.py # подключение к Qdrant
  paths.py      # общие пути к данным и токенизатору
tests/          # автономные проверки
evaluation/     # контрольные запросы в CSV
docs/           # подробные инструкции
data/, models/  # локальные данные, не входят в Git
```

## Установка

Нужен Python 3.10+. Для режима Gemma также нужны Docker Compose и ключ MWS. Команды выполняются из папки проекта.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Быстрый локальный поиск

Индекс для текущего корпуса уже построен. Запуск без MWS и Docker:

```bash
./run.sh --engine tantivy
```

На другом компьютере сначала поместите корпус в `data/corpus.sqlite3` и выполните `python -m habr_search.retrieval.tantivy_index build`. Откройте [localhost:8000](http://127.0.0.1:8000).

Tantivy ищет по словам, быстрее отвечает, но хуже понимает перефразировки. На контрольном наборе Hit@5 составил 72,22%, у Gemma — 97,22%. [Подготовка индекса, оценка и ограничения](docs/TANTIVY.md).

## Гибридный поиск

Для сравнения доступен режим Tantivy + BGE-M3. Он объединяет кандидатов по местам и использует один вызов MWS на запрос. При готовых индексах запуск:

```bash
./run.sh --engine hybrid
```

[Проверка готовности, метрики, продолжение отчёта и бесплатное сравнение весов](docs/HYBRID.md). Повторная индексация не нужна; улучшение качества пока требуется проверить.

## Поиск через BGE-M3

Для нового деплоймента `bge-m3` добавлен отдельный профиль с токенизатором BGE-M3 и векторами размерности 1024. Сначала нужно построить новую коллекцию и словарь: [пошаговая инструкция](docs/BGE_M3.md). После этого запуск:

```bash
./run.sh --engine bge-m3
```

Gemma пока сохранена для сравнения; без выбора режима используется прежний поиск.

## Поиск через Gemma

Для подготовленного индекса и словаря:

```bash
./run.sh
```

Скрипт запускает Qdrant, ждёт ответа базы и запускает страницу поиска с `data/spelling-full.sqlite3`. Если в проекте есть `.venv`, используется Python из неё; иначе — `python3`. Дополнительные параметры передаются приложению, например `./run.sh --port 8001`. Для остановки страницы нажмите `Ctrl+C`; Qdrant продолжит работать в фоне.

При первом запуске сначала поднимите Qdrant командой `docker compose up -d qdrant`, поместите корпус статей в `data/corpus.sqlite3` и [создайте индекс](docs/evaluation/EXPANDED.md). Корпус, индекс и словарь опечаток не входят в Git.

После индексации [постройте словарь опечаток](docs/evaluation/SPELLING.md):

```bash
python -m habr_search.retrieval.spellcheck build --qdrant-url http://127.0.0.1:6333 \
  --dictionary data/spelling-full.sqlite3
```

Если актуальный словарь уже существует, пропустите его построение. После изменения индекса создайте словарь в новый файл и укажите его путь при запуске.

После подготовки данных используйте `./run.sh`. Для запуска вручную:

```bash
docker compose up -d qdrant
python -m habr_search.web.app --qdrant-url http://127.0.0.1:6333 \
  --spelling-db data/spelling-full.sqlite3
```

Откройте [localhost:8000](http://127.0.0.1:8000). Ключ MWS вводится в терминале или берётся из `MWS_API_KEY`. Поиск и первичная индексация обращаются к платному API MWS.

Интерфейс показывает по пять статей. Кнопка «Показать ещё» раскрывает следующие результаты, всего до 20 на запрос, без дополнительных обращений к MWS.

Поиск из терминала:

```bash
python -m habr_search.retrieval.search --query "Как создавать отчёты Word из Excel?" \
  --qdrant-url http://127.0.0.1:6333
```
