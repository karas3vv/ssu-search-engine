# Расширенная проверка на 500 статьях

Старый `queries.csv` с 18 запросами остаётся стартовой проверкой. Для новых этапов подготовлены отдельные наборы по полным очищенным текстам из локального корпуса:

| Набор | Запросов | Статей | Назначение |
|---|---:|---:|---|
| `queries_dev.csv` | 32 | 8 | промежуточное сравнение и настройка алгоритмов |
| `queries_holdout.csv` | 16 | 4 | итоговая проверка после выбора настроек |

В каждой группе статей есть по одному запросу категорий `exact`, `paraphrase`, `alias` и `typo`. При разделении целиком отложена статья со всеми четырьмя вариантами: одна и та же статья не встречается в обоих наборах. Категория `alias` включает сокращения, переводы терминов и разговорные варианты названий; категория `typo` — намеренные ошибки в написании.

Разметка содержит известную подходящую статью для каждого вопроса. Полные тексты 12 целевых статей прочитаны, но все остальные статьи корпуса не размечены на релевантность к каждому запросу. Полезный результат с другим id может оказаться неучтённым: такие случаи нужно разбирать вручную и уточнять разметку. Запросы внутри одной статьи связаны между собой, поэтому 48 строк не равны 48 независимым темам.

Отложенный набор не следует запускать после каждой правки словарей или параметров. Сначала сравниваем варианты на `dev`, фиксируем настройки, затем проверяем `holdout`. Это заранее составленный набор для последней проверки, а не доказательство качества на всём Хабре. Корпус из первых 500 статей по id также не является случайной выборкой.

## Расширение индекса

Индексатор читает те же первые 500 принятых статей из `prepare.py`. На текущем корпусе пробное разбиение дало 2571 фрагмент, максимум 1016 токенов из 1024, без отклонённых записей. При неизменных настройках уже сохранённые 446 фрагментов первых 100 статей будут пропущены, останется получить 2125 векторов новых фрагментов.

```bash
python index.py --limit 500 --qdrant-url http://127.0.0.1:6333 --timeout 300
```

Команда обращается к MWS для новых фрагментов. `--timeout` ограничивает ожидание данных ответа одного пакета; подключение ограничено отдельно. Значение по умолчанию теперь 300 секунд, допускается также имя `--timeout-seconds`. Автоматических повторов нет. После остановки можно повторить ту же команду: подтверждённые точки будут пропущены. Изменение ожидания не меняет имя коллекции и id фрагментов.

Пока индекс не расширен, новые запросы могут не пройти проверку наличия ожидаемых статей. Все 12 целевых статей входят в первые 500 записей текущего подготовленного корпуса. Их номера в этом порядке указаны ниже.

## Оценка после завершения индексации

Проверить формат набора без MWS и Qdrant:

```bash
python evaluate.py --queries evaluation/queries_dev.csv --dry-run
```

Получить новый семантический отчёт на 32 запросах:

```bash
python evaluate.py --queries evaluation/queries_dev.csv \
  --qdrant-url http://127.0.0.1:6333 --timeout 300 \
  --output data/evaluation/dev-semantic-500.csv
```

Сравнить с BM25 на том же индексе без новых запросов к MWS:

```bash
python evaluate_bm25.py --queries evaluation/queries_dev.csv \
  --qdrant-url http://127.0.0.1:6333 \
  --semantic-report data/evaluation/dev-semantic-500.csv
```

Имена отчётов должны быть свободными; при повторном новом запуске задайте другое имя через `--output`. Если запуск прервётся, используйте `--resume` и частичный отчёт того же набора и размера индекса. Отчёты старых 18 запросов и результаты на 100 статьях для продолжения этого запуска не подходят. При оценке индекс должен оставаться неизменным.

Итоговый запуск отложенного набора выполняется после выбора настроек:

```bash
python evaluate.py --queries evaluation/queries_holdout.csv \
  --qdrant-url http://127.0.0.1:6333 --timeout 300 \
  --output data/evaluation/holdout-semantic-500.csv
```
