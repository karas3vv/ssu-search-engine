# Сравнение BM25 и семантического поиска

`bm25.py` ищет совпадения слов, а `search.py` ищет по векторной близости. Оба способа используют одну коллекцию Qdrant, ранжируют фрагменты, затем оставляют лучший фрагмент каждой статьи. BM25 получает только id, заголовки, ссылки и тексты; векторы не скачиваются. SQLite и MWS для BM25 не нужны.

## Как устроен BM25

Индекс строится в памяти при запуске команды. Текст каждого фрагмента объединяется с заголовком. Модель получает сокращённые длинные заголовки, BM25 использует полный заголовок. Никаких дополнительных весов заголовку не назначается.

Одинаковая обработка применяется к запросам и документам:

- нормализация Unicode NFKC, приведение к нижнему регистру, замена `ё` на `е`;
- выделение слов и чисел; окончания `++` и `#` сохраняются для названий вроде `C++` и `C#`;
- каждый уникальный термин запроса учитывается один раз.

Словоформы, стоп-слова, синонимы и опечатки специально не обрабатываются. Это исходный вариант для сравнения перед добавлением n-грамм, словарей и исправления опечаток.

Для каждого совпавшего термина используется формула:

```text
idf = ln(1 + (N - df + 0.5) / (df + 0.5))
score = сумма idf * tf * (k1 + 1) / (tf + k1 * (1 - b + b * length / average_length))
```

`N` — число фрагментов, `df` — число фрагментов со словом, `tf` — число его повторов во фрагменте. Длины учитывают заголовок. Параметры по умолчанию: `k1 = 1.2`, `b = 0.75`. Определение IDF и параметры описаны в [документации Lucene BM25Similarity](https://lucene.apache.org/core/9_12_1/core/org/apache/lucene/search/similarities/BM25Similarity.html). Здесь используется собственная небольшая реализация, зависимость от Lucene не требуется.

Частоты считаются по фрагментам. Перекрытия соседних фрагментов сохраняются, как и в семантическом индексе. Затем выбирается максимум оценки для каждой статьи. При равных оценках порядок определяется id статьи и точки. Результаты без совпадений слов не добавляются: выдача может быть короче `top_k` или пустой.

Оценки BM25 и косинусное сходство Gemma имеют разные шкалы. Сравнивать нужно позиции подходящих статей и метрики, а не сами значения оценок.

## Поиск из терминала

Все команды запускаются из корня проекта при работающем Qdrant:

```bash
python bm25.py --query "Как автоматически заполнять должности сотрудников в Excel?" --top-k 5 --qdrant-url http://127.0.0.1:6333
```

Ключ MWS и файл токенизатора не нужны. Адрес MWS и имя деплоймента из окружения используются только для вычисления имени той же коллекции. Серверные `QDRANT_URL` и `QDRANT_API_KEY` поддерживаются так же, как в остальных командах. Параметры `--max-tokens` и `--overlap-tokens` должны совпадать с индексацией. `--k1` и `--b` изменяют настройки BM25; их значения сохраняются в отчёт оценки.

## Оценка и сравнение

Только BM25 на контрольных запросах:

```bash
python evaluate_bm25.py --qdrant-url http://127.0.0.1:6333
```

Сравнение с полным сохранённым отчётом Gemma:

```bash
python evaluate_bm25.py --qdrant-url http://127.0.0.1:6333 \
  --semantic-report data/evaluation/results-20261019-090607-976533.csv
```

Имя файла следует заменить своим. Поддерживаются `--queries`, `--limit` и `--top-k`. При сравнении выбранный набор, разметка, коллекция, число фрагментов и `top_k` должны совпадать с отчётом Gemma. Частичный семантический отчёт отклоняется. Если Gemma запускалась с `--raw-query`, для сравнения укажите `--semantic-raw-query`. Старый отчёт не изменяется, а повторных обращений к модели нет.

CSV сохраняется в `data/evaluation/bm25-<время UTC>.csv`, путь меняется через `--output`. Существующий файл не перезаписывается. В отчёте указаны метод, версия BM25, `k1`, `b`, хеш прочитанных текстов и метаданных, набор запросов, ожидаемые и найденные id, места и обратные места. При сравнении добавляются путь к отчёту Gemma и её результаты по каждому запросу. Формат отличается от семантического отчёта, поэтому его нельзя передать в `evaluate.py --resume`.

Коллекция читается повторно перед записью отчёта BM25; при изменении текстов или метаданных запуск останавливается. Старые отчёты Gemma содержат имя коллекции и число точек, но не хеш содержимого: они не позволяют доказать, что тексты не заменялись с сохранением числа точек. Поэтому между оценками индекс должен оставаться неизменным. Параметры BM25 и контрольный набор также нужно фиксировать при сравнении.

## Первая проверка на 100 статьях

На 446 фрагментах, 100 статьях и стартовых 18 запросах получено:

| Метод | Hit@5 | MRR@5 |
|---|---:|---:|
| Gemma, сохранённый отчёт | 18/18 (100%) | 1.0000 |
| BM25, k1=1.2, b=0.75 | 16/18 (88.89%) | 0.7361 |

BM25 дал такое же обратное место первой подходящей статьи на 11 запросах и худшее на 7. Это измерения на стартовом наборе с предварительной разметкой по шести статьям, а не оценка качества на всём Хабре. Новые возможности нужно проверять и на дополнительных темах и запросах, которые не использовались при настройке.
