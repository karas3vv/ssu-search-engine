# Контрольные запросы для поиска

`queries.csv` содержит 18 стартовых проверок по шести статьям, которые уже встречались в выдаче на корпусе из 100 статей. Набор подготовлен по заголовкам, показанным отрывкам и выполненным вручную поисковым запросам. Разметка предварительная и неполная: её нужно сверить с полными текстами и расширить статьями из других тем.

Это проверки работоспособности и начальное сравнение вариантов поиска. Несколько формулировок относятся к одной статье, а темы сосредоточены вокруг офисной автоматизации. Итоговые результаты нельзя переносить на весь Хабр. После настройки алгоритмов потребуется отдельный набор запросов, который не использовался при настройке.

## Формат набора

Все команды выполняются из корня проекта. CSV хранится в UTF-8 и редактируется обычным текстовым редактором:

```csv
query_id,category,query,relevant_article_ids
positions_exact,exact,Как автоматически заполнять должности сотрудников в Excel?,891074
```

- `query_id` — уникальное имя проверки латиницей, цифрами и символами `_` или `-`.
- `category` — группа: `exact` для прямых запросов, `paraphrase` для перефразировок, `alias` для вариантов названий, `typo` для опечаток. Можно добавлять свои группы.
- `query` — текст запроса.
- `relevant_article_ids` — хотя бы один id ожидаемой статьи. Несколько id разделяются `;`: например, `795057;888510`.

В наборе отмечены известные подходящие статьи, а не все возможные релевантные результаты. Неотмеченная статья тоже может оказаться полезной. Все перечисленные id должны присутствовать в индексе; при отсутствии хотя бы одного скрипт останавливается до обращения к MWS. Поиск по словам, словарь синонимов, n-граммы и исправление опечаток ещё не реализованы. Категории запросов позволяют в дальнейшем сравнить их влияние.

Первые три строки повторяют уже проверенные запросы к статьям:

- `795057` и `888510` — создание документов Word с использованием данных Excel и Python;
- `891074` — должности сотрудников в Excel;
- `575278` — Power Automate Desktop.

Остальные проверки также используют `717902` (ExecuteExcel4Macro) и `821879` (Python in Excel).

## Запуск

Проверка структуры CSV без Qdrant, MWS, скачивания токенизатора и создания отчёта:

```bash
python evaluate.py --dry-run
```

Этот режим не проверяет наличие статей в индексе и длину входа для модели.

Пробная оценка первых трёх запросов на существующем серверном индексе:

```bash
python evaluate.py --limit 3 --qdrant-url http://127.0.0.1:6333
```

Весь набор:

```bash
python evaluate.py --qdrant-url http://127.0.0.1:6333
```

Ключ вводится один раз или берётся из `MWS_API_KEY`. Затем выполняется по одному обращению к MWS для каждого выбранного запроса: 3 обращения для `--limit 3` или 18 для полного набора. Повторный запуск снова получает векторы запросов. Векторы статей не пересчитываются, SQLite не читается, поисковый индекс не изменяется.

Параметры `--max-tokens`, `--overlap-tokens`, адрес MWS и деплоймент должны совпадать с индексацией. `--raw-query` выбирается так же, как в `search.py`: только если сервер сам добавляет инструкцию Gemma. Перед вводом ключа проверяются коллекция, ожидаемые статьи и длины всех выбранных запросов вместе с инструкцией.

## Метрики

Оцениваются разные статьи, сгруппированные через тот же `search_articles`, что использует `search.py`. По умолчанию `k = 5`, его можно изменить через `--top-k`.

- **Hit@k** — доля запросов, у которых хотя бы одна отмеченная подходящая статья найдена в первых `k` результатах. Эта метрика также называется Success@k.
- **MRR@k** — среднее обратное место первой отмеченной подходящей статьи: место 1 даёт `1`, место 2 — `0.5`, место 5 — `0.2`. Если статья не найдена в первых `k`, вклад равен `0`.

Например, для мест `1`, `2` и пропуска Hit@5 равен `2/3`, а MRR@5 равен `(1 + 0.5 + 0)/3 = 0.5`. При нескольких подходящих статьях достаточно первой. Сводка выводится для всего набора и отдельно по категориям. Precision@k и Recall@k пока не рассчитываются: для содержательной оценки нужна более полная разметка релевантности.

Определения: [Success](https://ir-measur.es/en/latest/measures.html#success), [Reciprocal Rank](https://ir-measur.es/en/latest/measures.html#rr) в документации ir-measures. Дополнительная библиотека для расчёта этих двух метрик не нужна.

## Отчёт и сопоставимость запусков

CSV-отчёт сохраняется в `data/evaluation/results-<время UTC>.csv` и исключён из Git вместе с `data/`. Для собственного пути используйте `--output путь.csv`; существующий файл не перезаписывается.

Для каждого запроса записываются время начала, имя коллекции, число фрагментов, хеш выбранного набора запросов, режим инструкции, `top_k`, ожидаемые и найденные id, место и обратное место. Один и тот же хеш означает одинаковые выбранные запросы и разметку в одинаковом порядке.

Каждая завершённая проверка сразу сохраняется в отчёт. При ошибке или остановке файл может быть неполным; итоговые метрики для неполного запуска не выводятся. Автоматическое продолжение частичного отчёта пока не поддерживается. После исправления причины выполните новый запуск; предыдущий отчёт останется на месте.

Во время оценки не обновляйте индекс. Изменение числа фрагментов обнаруживается проверкой в конце запуска; замена текстов и векторов с сохранением их количества этой проверкой не выявляется. Для сравнения с будущим BM25 нужно использовать одинаковый состав статей, тот же набор запросов и тот же `top_k`.
